**Микросервисная архитектура** - большая программа, которая разделена на маленькие приложения, которые работают самостоятельно. На Python принято писать так.

Django создан для написания монолитов.

**Параллельное программирование** - каждое ядро выполняет свою задачу
**Асинхронное программирование** - приложение выполняет другой фрагмент кода, если ожидается результат выполнения какой-либо другой части программы. 

Django не умеет в асинхронное программирование, поэтому будем изучать **FastAPI**, где программа более гибкая.

В Python очень легко реализовано асинхронное программирование

```python
def f1(): return # синхронная функция.
async def f1(): return # асинхронная функция.
```

С асинхронной функцией не будет работать ожидание результата обычным способом.

```python
async def f1(): 
   ...
   await f2()

await res = f1()
```

# Архитектура REST
Работа `get`, `post` и прочих запросов - принятые соглашения. Для выполнения посылается запрос в базу. 

`https://myback.ru/posts/10`

```python
get("/posts/{id}")
```

Любой API называют "ручкой". Потому что это как протянутая рука, которая ждёт Handshake или вызов функции.

`get` - не умеет получать JSON. API для получения данных.
`post` - умеет получать JSON. API для отправки данных
`put` - умеет получать JSON. API для изменения существующих данных.
`delete` - не умеет получать JSON. API для удаления данных.

URL - адрес, состоит из нескольких частей:
- Протокол
- Сервер
- Адрес на сервере

JSON - формат хранения данных. 

Четыре основные операции - `CRUD`:
- CREATE - создание
- READ - чтение
- UPDATE - обновление
- DELETE - удаление
С помощью этих четырёх функций можно реализовать всё, что угодно
