Идентификаторы являются типами данных

`SYMBOL`

```lisp title:"Symbol-функции"
(symbol-value 'A) ; Получение значения
(symbol-name 'A) ; Получение имени значения
(symbol-function 'A) ; Функция возвращает функцию, результатом которой будет значение
```

Один идентификатор может быть одновременно и именем функции и значением переменной

```LISP
(defun f (...))
(setq f 25) ; значение не затеняется
```

Функция сама может являться значением

```LISP title:"Определение Lamda-функции"
(setq f (lambda (x) (+ x 25))) => 
(defun f (x) (+ x 25))
(f 3) => 28

(apply function (arg1 arg2 agr3 ...))
(apply f (3)) => 28 ; применится лямбда-функция f
(apply 'f (3)) => 28 ; получает идентификатор в качестве первого аргумента (имя функции), ищет фукнцию, которая скрывается за этим идентификатором
(funcall function arg1 arg2 ...)
(funcall f 3)
(funcall 'f 3)
```

`apply` принимает в качестве аргумента функцию (неважно, как она задана)

# Принципы создания языков программирования
- Принцип сундучка
- Принцип чемоданчика

## Принцип сундучка
Когда на все случаи жизни заведены конструкции (для всего есть собственная функция)
Большой язык программирования, освоить сложно


*Пример*:
<u>Common LISP</u>, который объединил в себе все диалекты LISP

## Принцип чемоданчика
Есть самые необходимые базовые функции в ядре
Остальное реализуется с помощью ядра
Малое ядро языка
Позволяют расширять язык, подстраивая его под себя

*Пример*:
<u>Python</u>, в котором можно подключать сторонние библиотеки для решения той или иной задачи, где функции реализованы через базовые функции языка
<u>C</u> с базовым ядром

Расширять язык можно с помощью специальных <mark style="background: #BBFABBA6;">макросов</mark>

# Макросы
Макрос |=> Текстовая замена

```C title:"Макросы в C"
#DEFINE M 3 // Дурацкий пример макроса, когда M заменяется на 3 в ходе выполнения программы
#DEFINE SQR(X) (x + x * x)
```

`#` в начале - директива препроцессору, выполняется до этапа компиляции

```LISP title:"Макросы в LISP"
(defmacro sqr(x) 
  (list '+ x (list '* x x)))

(sqr 25)
; (+ 25 (* 25 25))
```

Так как макрос - текстовая замена, то аргументы не вычисляются заранее, если передать выражение, то сформируется новая функция с другими приоритетами


```LISP title:"Оптимизация Макросов в LISP"
(defmacro sqr (x) 
  (list 'let (list list 'a x))
    (list '+ 'a (list '* 'a 'a))))

(defmacro sqr (x)
  `(let ((a ,x))
    (+ a (* a a))))
```

```LISP
(defmacro sqr (x)
  `(let ((a ,x))
    (+ a (* a a))))

(setq i 1)
(sqr (incf i))
  (+ (incf i) (* (incf i) (incf i)))
```

`incf` первый аргумент - переменная, увеличивается на единицу
`decf` - декремент

```CPP
#DEFINE SQR(x) (x + x * x)
SQR(5+4); // 5 + 4 + 5 + 4 * 5 + 4;
```

```LISP
(defmacro if-equal (exrp1 exrp2 expr3 expr4)
  `(let ((a ,exrp1)
         (b ,expr2))
    (if (= (* a a) (* b b)) ,expr3 ,expr4)))

(if-equal 3 5 (cons 'A 'B) (cdr (a b c)))

(setq a 1)
(setq b 5)
(if-equal 3 5 (list a b) (list a a b b))

(let ((a 3) (b 5))
  (if (= (* a a) (* b b)) (list a b)
    (list a a b b)))
```


```LISP title:"Использование без перекрытия пространства имён"
(defmacro if-equal (exrp1 exrp2 expr3 expr4)
  (let ((a (gensym)) (b (gensym))))
    `(let ((,a ,exrp1)
           (,b ,expr2))
      (if (= (* ,a ,a) (* ,b ,b)) ,expr3 ,expr4))))
```

```LISP title:"Отличие defmacro от defun"
(defmacro m (...)) ; список аргументов может иметь структуру, в отличие от списка аргументов в defun

(defmacro m (a1 (a2 a3 (a3 a5) a6) a7 ..))
```

В макросах принято использовать `&body` вместо `&rest`

```lisp
(defmacro m (a1 (a2 &optional a3 a4 &body a5) &optional a6 a7 &body a8))
```
