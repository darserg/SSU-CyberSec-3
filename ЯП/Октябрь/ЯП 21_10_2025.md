# SML
## Операции над списками
### Zip
Пример работы zip
```
[1, 2, 3, 4, 5] ["a", "b", "c", "d"]
[(1, "a"), (2, "b"), (3, "c"), (4, "d")]
```

```sml
fun zip [] _ = [] (* Соединение *)
  | zip _  [] = []
  | zip (x :: xs) (y : ys) = (x, y) :: zip xs ys
```

### ZipWith
```sml
fun zipWith _ [] _ = []
  | zipWith _ _ [] = []
  | zipWith f (x :: xs) (y :: ys) = f (x, y) :: zipWith f xs ys
```

Пример работы zipWith
```sml
zipWith (op +) [1, 2, 3, 4] [5, 6, 8, 9] = [6, 8, 11, 13]
```

## Замыкание
```sml
fun f x = x * 25  (* ("f", [x], x * 25, [....]) *)
                  (* (f, ("f", [x], (x * 25), [....])) *)
val g = f         (* (g, (f, ("f", [x], (x * 25), [....])), [....]) *)

(* Не имеет смысла, т.к. лишнее обёртывание в ДО *)
fun g1 x = f x    (* (g1, ("g1", [x], f x, [....])) *)

```

## Макрос mLet
Этот макрос необходим для переопределения функции

```SML
fun zipWith _ [] _ = []
  | zipWith _ _ [] = []
  | zipWith f (x :: xs) (y :: ys) = f (x, y) :: zipWith f xs ys


val f1 = zipWith (op +) [1, 2, 3]

f1 [3, 4] (* => [4, 6] *)
f1 []     (* => [] *)


(* ПЛОХО, двойное оборачивание в замыкание *)
fun f2 l = zipWith (op +) [1, 2, 3] l  (* f1 также входит в замыкание f2 *) 
```

# Haskell
Рассматриваем `Haskell` из-за некоторых его особенностей:
1. Двумерный синтаксис
2. Ленивые вычисления (Мемоизация - в места, где используется выражение, передаём значение выражения)


```sml
(* Нормальные вычисления *)
fun sumOfSquares (x, y) = square x + square y
fun square a = a * a
sumOfSquares (15 - 6, 8 - 4)
             (*  #1    #2 *)
    (* square (#1) + square (#2) *)
    (* (#1) * (#1)               *)
    (* 9 * (#1)                  *)
    (* 9 * 9                     *)
    (* 81                        *)
    (* 81          + square (#2) *)
    (* 81          + (#2) * (#2) *)
    (* 81          + 4 * (#2)    *)
    (* 81          + 4 * 4       *)
    (* 81          + 16          *)
    (* 97 *)
    
```

**Мемоизация** - процесс, при котором значение выражений ==многократно *отрисуемых*== вычисляются и хранятся на месте этих выражений


> [!Программы с ленивыми вычислениями, можно сказать, выполняются с конца]


```sml
val a = выражение
fun f .... = выражение
```

```haskell
a = выражение
f .... = выражение

a = 25 + x

fact 0 = 1
fact n = n * fact (n - 1)
```

Отличие интерпретатора Haskell от интерпретатора SML - в интерпретаторе можно узнать только значение выражения

В Haskell-интерпретаторе нельзя задавать многострочные выражения

```repl
- 7 + x
- let x = 5 in 7 + x
```

## Ленивые вычисления
```haskell
a = 15

c = a + b
d = 147 * a
f = div c 0 \comment "Функции двух аргументов в Haskell по умолчанию каррированы"
```

```haskell
a = 15
b = 27
c = a + b
d = 147 * a
f = div c 0
l = map (1+) (a : d : b : []) \comment "Эквивалент [a, d, b]"
```

## Формы значений выражений на Haskell
1. `thunk` - невычисленное выражение
2. Нормальная форма - полностью вычисленное выражение
3. Дно $\perp$
4. Слабая головная нормальная форма
   Выражение вычислено до слабой головной нормальной формы, если оно вычислено до вызова конструктора, параметрами которого являются значения в любой форме

## Отдельные моменты
- В `Haskell` любую операцию можно превратить в инфиксную форму из префиксной, взяв знак операции в круглые скобки
- Определение функций в Haskell может быть в любом порядке, благодаря ленивым вычислениям
- В программе не может быть сущностей с одинаковыми именами
