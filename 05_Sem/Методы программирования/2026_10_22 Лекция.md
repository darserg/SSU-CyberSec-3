# Алгоритм тернарного поиска
Этот алгоритм схож с алгоритмом бинарного поиска, но несмотря на схожесть этих методов, не стоит воспринимать их как одно и то же, функции будут, зачастую, очень сильно различаться

Тернарный поиск чаще всего используется для поиска минимума или максимума какой-то функции на отрезке, то есть, чаще всего у нас будет такая формулировка задачи:
> есть некоторая функция, дан некоторый отрезок и нужно в этом отрезке найти минимальное или максимальное значение функции


**Тернарный поиск можно применять далеко не на каждой функции**. Мы будем его применять на унимодальных функциях

*Что такое унимодальная функция?* 
Функция должна иметь один из следующих двух видов: 
- Три отрезка - отрезок строгого убывания, отрезок константы, отрезок строгого возрастания
- Три отрезка - отрезок строгого возрастания, отрезок константы, отрезок строгого убывания

Какие-то из отрезков могут быть вырожденными
Должно быть не более одного отрезка каждого типа


Если производная монотонная - наша функция всегда будет удовлетворять нашему условию

Как правило, доказать, что функция возрастает этим ограничениям, будет не сложно

## Поиск максимума в функции при помощи тернарного поиска (нецелочисленные значения)
Изначально мы знаем, что ответ в отрезке (l, r) 
И надо длину отрезка сделать меньше $\epsilon$


Выберем две точки - $m_{1}, m_{2}$. Изначально эти отрезки будут равными:
$$
m_{1} = L + \frac{R-L}{3}
$$
$$
m_{2}= L + \frac{(R-L)\cdot 2}{3}
$$

Сравним значения функции в $m_{1}\text{ и }m_{2}$ и определим, какое из значений "лучше" - больше или меньше, в зависимости от поставленной задачи

```
if f(m1) better f(m2):
	R = m2
else:
	L = m1
```

Теперь рассмотрим различные способы деления отрезка: 
Нужно сделать так, чтобы левая и правая часть были больше центральной

В таком случае мы можем вычислить значение таким образом: 
```
m1 = L + (R - L) * 0.45
m2 = L + (R - L) * 0.55
```

Так мы будем каждый раз уменьшать отрезок почти в два раза

Если мы делаем эти части разного размера, то в лучшем случае мы получаем ответ в лучшем случае, а если делаем части одинаковыми - лучшего и худшего случая не существует 

Проблемы того, почему нельзя писать цикл вида: 
```python
while (r - l) > eps
```

В такой ситуации можно получить бесконечный цикл, например, если расстояние между "равными" числами L и R может быть больше eps

Может быть такое, что 
L и R представимы в памяти компьютера, но никакое число между ними не представимо

Изначально нужно умененьшить отрезок в 
$$
 \frac{R-L}{\epsilon}
$$

Здесь, учитывая, что отрезок каждый раз уменьшается в $k$ раз

$$
k = \frac{1}{1 - x}
$$

Итого потребуется
$$
\log_{k} \frac{R-L}{\epsilon} + 1 = \log_{\frac{1}{1-x}} \frac{R -L}{\epsilon}
$$

```python
import math

LK = math.log2(1.0 / (1.0 - 0.45))
EPS = 1e-9


def f(x):
    return 10.0 * math.sqrt(x) - 0.5 * x**2


def find_greatest_arg(L, R):
    iters = int(math.log2((R - L) / EPS) / LK) + 1
    for _ in range(iters):
        m1 = L + (R - L) * 0.45
        m2 = L + (R - L) * 0.55
        fm1 = f(m1)
        fm2 = f(m2)
        if fm1 > fm2:  # f(m1) лучше f(m2)
            R = m2
        else:
            L = m1
    return (L + R) / 2


def find_smallest_arg(L, R):
    iters = int(math.log2((R - L) / EPS) / LK) + 1
    for _ in range(iters):
        m1 = L + (R - L) * 0.45
        m2 = L + (R - L) * 0.55
        fm1 = f(m1)
        fm2 = f(m2)
        if fm1 < fm2:
            R = m2
        else:
            L = m1
    return (L + R) / 2


if __name__ == "__main__":
    print(find_greatest_arg(0.0, 100.0))
    print(find_smallest_arg(0.0, 100.0))

```

## Двумерный тернарный поиск
Пусть существует некоторая прямоугольная область, в которой существует функция от двух аргументов 

f(x, y) - min
$(R_{x}, R_{y}); (L_{y}, L_{y})$ - координаты области

Введём вспомогательную функцию $g(x) = \min(f(x,y)) : y \in [L_{y}, R_{y}]$

Внешний тернарный поиск по $g(x)$, а чтобы вычислять значение функции $g(x)$ - будем делать внутренний тернарный поиск по $y$ для вычисления $g(x)$

```python
import math

LK = math.log2(1.0 / (1.0 - 0.45))
EPS = 1e-9


def f(x, y):
    return ((x - 5.0) ** (x - 5.0)) + (abs(y - 6.5))


def find_best_y(x, Ly, Ry):
    l = Ly
    r = Ry
    iters = int(math.log2((r - l) / EPS) / LK) + 1
    for _ in range(iters):
        m1 = l + (r - l) * 0.45
        m2 = l + (r - l) * 0.55
        fm1 = f(x, m1)
        fm2 = f(x, m2)
        if fm1 < fm2:
            r = m2
        else:
            l = m1
    return (l + r) / 2


def g(x, Ly, Ry):
    # g(x) - min(f(x, y)) по всем y \in [Ly, Ry]
    return f(x, find_best_y(x, Ly, Ry))


def find_best_x(Lx, Rx, Ly, Ry):
    l = Lx
    r = Rx
    iters = int(math.log2((r - l) / EPS) / LK) + 1
    for _ in range(iters):
        m1 = l + (r - l) * 0.45
        m2 = l + (r - l) * 0.55
        fm1 = g(m1, Ly, Ry)
        fm2 = g(m2, Ly, Ry)
        if fm1 < fm2:
            r = m2
        else:
            l = m1
    return (l + r) / 2


def find_best_point(Lx, Rx, Ly, Ry):
    x = find_best_x(Lx, Rx, Ly, Ry)
    y = find_best_y(x, Ly, Ry)
    return [x, y]


if __name__ == "__main__":
    print(find_best_point(-50.0, 50.0, -100.0, 100.0))

```
