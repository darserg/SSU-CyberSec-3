# Асимптотическая сложность (асимптотика программ)
Чтобы измерить время работы программы используется обычно один из двух вариантов:
- **Асимптота** - анализ программы по специальным правилам
- **Бенчмарк** - есть готовая программа, на неё берётся большой объём данных и измеряется число времени, которое нужно для исполнения этой программы для данного объёма. Преимущество - даёт явное время работы программы на конкретных данных. Минус - бенчмарк зависит от конкретных данных. Сложность в том, чтобы понять, как именно подобрать данные, какие данные будут показывать худший случай работы программы и найти где этот случай будет выражаться


Асимптотический анализ показывает <u>зависимость</u> времени работы от размера входных данных. Показывает, как быстро растёт время работы программы в зависимости от входных данных

Результат - математическая функция, как правило одного аргумента, в некоторых случаях от нескольких

Мы будем писать это в формате $O(n)$, $O(n^2)$, $O(n \log n)$. $O$ - верхняя оценка на программе

Что обозначает каждая из таких функций
$T(n)$ - время работы программе при размере входных данных $n$
$T(n)$ - это $O(f(n))$, если $\exists c > 0 \space \exists n_{0} > 0 \space \forall n \geq n_{0}: \space T(n) \leq c^* f(n)$

![[Drawing 2026-09-03 12.54.10.excalidraw]]


Любая программа, выполняемая за $O(n)$ на самом деле выполняется и за $O(n^2)$, $O(n^3)$, и тд.
Это на первый взгляд выглядит как проблема в теории, но на самом деле есть некоторые случаи, когда это имеет смысл

> Мы оцениваем время работы программы в худшем случае


В асимптотическом анализе есть такая неприятная вещь, как скрытая константа $c$. Для того, чтобы приблизительно выяснить эту константу, необходимо запускать программу на некоторых данных

Пусть мы получили функцию $O(3.5n)$, с точки зрения асимптотического анализа мы получили то же самое что и $O(n)$

Обычно работает "правило большого пальца" - это прикидка на глаз времени работы программы. Система должна обрабатывать объём данных до определённого размера. Мы можем подставить этот размер в получившуюся функцию и сравнить с числом порядка $2*10^8$ или $3*10^{8}$, если число будет меньше, то функция точно выполнится за секунду на практически любой современной системе

Это позволяет быстро отбрасывать плохие варианты. Допустим, у нас есть набор данных из 100-200 тысяч данных и функция работает за $O(n^2)$, то алгоритм неэффективен

Один из стандартных примеров - встроенные методы сортировки в Java/C++, которые в случае небольшого объёма данных переключаются на алгоритм с $O(n^2)$

Асимптотический анализ наиболее эффективен при больших наборах данных


## Как определить время выполнения программы?

Два правила: 
1. Правило сложения
	   Берём разбиваем программу на блоки, которые выполняются один за другим: 
	   $$
	\left.\begin{array}l
	1. & O(f(n)) \\
	2.  & O(g(n))
	\end{array}\right\} O(f(n) + g(n))
	   $$
2. Правило умножения
	   Вложенные блоки: 
   $$
	\left.\begin{array}l
	1. & O(f(n)) \\
	2.  & O(g(n))
	\end{array}\right\} O(f(n) * g(n))
	   $$
	   Или когда одна функция выполняется несколько раз
3. Правило поглощения
	   Функция, которая растёт не медленнее, чем другая, будет поглощаться


Рассмотрим на примере:
```cpp
#include <iostream>

using namespace std;


int main()
{
  int n;                        // O(1)
  cin >> n;                     // O(1)

  vector<int> a(n);

  for (int i = 0; i < n; i++)   // O(n)
    cin >> a[i];                // O(1)

  long long sum = 0;            // O(1)

  for (int i = 0; i < n; i++)   // O(n)
    sum += a[i];                // O(1)

  cout << sum << endl;          // O(1)
}
```

### Как оценивать базовые операции?
Сложение, вычитание и тд. Все эти функции выполняются за $O(1)$ - не зависят от размера входных данных

Обычно можно найти время выполнения стандартной функции в документации


### Второй пример
```cpp
#include <iostream>

using namespace std;


int f1()
{
  int n;
  cin >> n;

  vector<int> a(n);

  for (int i = 0; i < n; i++)
    cin >> a[i];

  long long sum = 0;

  for (int i = 0; i < n; i++)
    sum += a[i];

  cout << sum << endl;
}

int f2()
{
  int n;
  cin >> n;
  int k;
  cin >> k;
  bool res = false;
  vector<int> a(n);
  for (int i = 0; i < n; i++)
    for (int j = 0; j < i; j++)
      if (a[i] + a[j] == k)
        res = true;

  if (res)
    cout << "YES\n";
  else
    cout << "NO\n";
}
```

```python
n = int(input())
k = int(input())
a = list(map(int, input().split()))
res = False

for i  in range(n):           # O(n)
    for j in range(i):        # O(n)
        if a[i] + a[j] == k:  # O(1)
            res = True        # O(1)

print('YES' if res else 'NO')
```

Программа работает за $O(n^2)$

### Третий пример
```cpp
#include <iostream>

using namespace std;

void f1()
{
  int n;
  cin >> n;

  vector<int> a(n);

  for (int i = 0; i < n; i++)
    cin >> a[i];

  long long sum = 0;

  for (int i = 0; i < n; i++)
    sum += a[i];

  cout << sum << endl;
}

void f2()
{
  int n;
  cin >> n;
  int k;
  cin >> k;
  bool res = false;
  vector<int> a(n);
  for (int i = 0; i < n; i++)
    for (int j = 0; j < i; j++)
      if (a[i] + a[j] == k)
        res = true;

  if (res)
    cout << "YES\n";
  else
    cout << "NO\n";
}

int main()
{
  int n;
  cin >> n;
  vector<bool> prime(n + 1);
  for (int i = 2; i <= n; i++)
    prime[i] = true;

  for (int i = 2; i <= n; i++)
    for (int j = i * 2; j <= n; j += 1)
      prime[j] = false;

  int k = 0;
  for (int i = 0; i <= n; i++)
    if (prime[i])
      k++;
  cout << k;
}
```


Запустим для 100000. Увидим результат довольно скоро. Быстрее, чем за $O(n^2)$. При детальном рассмотрении мы получим, что вложенный цикл работает за
$O\left( \frac{n}{2} + \frac{n}{3} + \frac{n}{4} + \dots + \frac{n}{n} \right)$ ~ $O(n \log n)$
