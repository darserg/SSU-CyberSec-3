# Симтотический анализ рекурсии
$$
\text{глубина рекурсии} \times \text{работа на каждом уровне}
$$

# Алгоритмы сортировок
Для сортировок есть много разных важных разделений: 
- По типу
- Как ведут себя с разными данными
- По времени


Но нам нужно разделение на: 
1. Сортировки, основанные на сравнениях
   Преимущество - такие сортировки общеприменимы, используются для любого типа данных
   Минус таких сортировок - всегда не лучше $O(n\log n)$ в худшем случае
2. Сортировки, основанные не только на сравнениях
   Минус таких сортировок - заточены под конкретный тип данных, нельзя применять в общем случае


Принципиальная разница между этими категориями заключается в том, что сортировки, основанные на сравнениях - мы можем сравнивать элементы и менять их местами, иногда копировать. Сортировки, основанные не только на сравнениях, могут использовать ещё какие-то свойства элементов для того, чтобы сортировать массив


Сортировка подсчётом (пример сортировки, основанной не толко на сравнениях):
```python
a = [0, 2, 3, 1, 2, 6] # пример
b = [0 for i in range(N)]

for x in a:
	b[x] += 1

b = [1, 1, 2, 1, 0, 0, 1]
```
Работает за $O(|a| + N)$

Сортировка, основанная не на сравнениях всегда работает на определённый тип данных, в определённых границах


В стандартных библиотеках современных языков программирования обычно используется как раз сортировка, основанная на сравнении

## Сортировка вставками
> Работает за $O(n^2)$ в худшем случае

Хорошо работает на малых объёмах данных

Основная идея алгоритма сортировки вставками заключается в следующем:

Есть массив, который мы хотим отсортировать
Для каждого элемента, слева направо, начиная со второго, мы попробуем протащить его влево, пока он не встанет на правильную для себя позицию

Пример:
```
5 1 2 4 3 6
1 5 2 4 3 6
1 2 5 4 3 6
1 2 4 5 3 6
1 2 3 4 5 6
```


```python
def insertion_sort(a):
    n = len(a)
    for i in range(1, n):                               # O(n)
        # пытаемся протащить a[i] влево
        j = i
        while j > 0 and a[j] < a[j-1]:                  # O(n)
            a[j], a[j-1] = a[j-1], a[j]
            j -= 1
    return a
```

Тогда суммарное время работы программы будет по правилам умножения в худшем случае - $O(n^2)$, в лучшем случае - $O(|a| + N)$. Лучший и худший случай зависят от того, насколько отсортированы данные до попадания в алгоритм

Каждая итерация while делает массив более отсортированным

## Быстрая сортировка (quick sort)
Самый частоприменяемый алгоритм сортировки
> Работает за $O(n \log n)$* 

Звёздочка означает, что в разных реализациях Quick Sort может быть за другое время выполнения. Во многих реализациях время уйдёт в $O(n^2)$

Изначальная идея реализации работала в $O(n^2)$, дальнейшее развитие - работа за $O(n\log n)$ возникло позже, при более хороших реализациях

Основной принцип Quick Sort:
Есть массив, который нужно отсортировать. В этом массиве выбирается опорный элемент - pivot. И этот массив делится на две или три части. Лучше писать с разделением на 3 части. Так, при поступлении в программу массива со всеми одинаковыми элементами, программа не уйдёт в $O(n^2)$. Три части на которые нужно разделить:
1. Элементы, меньшие опорного
2. Элементы, равные опорному
3. Элементы, большие опорного

Для первого и второго массива запускаем алгоритм через рекурсивный вызов

Для определения всех этих элементов, нужно сделать линейный проход через все элементы массива

Одна из самых важных частей Quick_Sort - разделение элементов на три части внутри самого массива без выделения дополнительной памяти (in place partition)

Какие существуют методы разделения: 
1. Схема Ломуто
   Допустим, мы обработали сколько-то первых элементов массива и знаем, где находится граница между тем, что меньше опорного и больше или равно опорному. Каждый следующий элемент нужно добавить либо в первую либо во вторую группу. Неоптимальна. Работает за $O(n^2)$
2. Схема Хоара



Хотелось бы, чтобы размер левой части не сильно отличался от размера правой части, чтобы каждое разделение выполняло примерно равное количество работы
Если разделение будет хорошим, то глубина рекурсии будет $O(\log n)$, если плохим - $O(n)$

На каждом уровне рекурсии будет $O(n)$ действий, поэтому асимптотика будет $O(n)\times\text{глубина рекурсии}$

Модифицированная схема Ломуто:
```cpp
#include <iostream>

using namespace std;

pair<int, int> partition(vector<int> &a, int l, int r)
{
  // разделить полуинтервал [l, r)
  // вернуть границы разделения
  // (начало центрального блока,
  // начало правого блока)
  auto pivot = a[l];
  int k1 = l, k2 = l;
  // k1 - среди уже обработанных элементов начало блока равных опорному
  for (int i = l; i < r; i++)
  {
    if (a[i] <= pivot)
    {
      swap(a[i], a[k2]);
      if (a[k2] < pivot)
      {
        swap(a[k2], a[k1]);
        k1++;
      }
      k2++;
    }
  }
  return {k1, k2};
}

template <typename T>
void quickSort(vector<T> &a, int l, int r)
{
  if (l >= r - 1)
    return;

  pair<int, int> p = partition(a, l, r);
  quickSort(a, l, p.first);
  quickSort(a, p.second, r);
}

int main()
{
}
```


```python
def partition(a, l, r):
    # разделить полуинтервал [l, r)
    # вернуть границы разделения
    # (начало центрального, начало правого)
    pivot = a[l]
    k1 = l
    k2 = l 
    # k1 - среди уже обработанных элементов начало блока равных опорному
    for i in range(l, r):
        if a[i] <= pivot:
            a[i], a[k2] = a[k2], a[i]
            if a[k2] < pivot:
                a[k2], a[k1] = a[k1], a[k2]
                k1 += 1
            k2 += 1
    return (k1, k2)


def quick_sort(a, l, r):
    # l - начало сортируемого промежутка
    # l - конец* сортиреумого промежутка
    if l >= r - 1:
        return

    px, py = partition(a, l, r)
    quick_sort(a, l, px)
    quick_sort(a, py, r)
```
