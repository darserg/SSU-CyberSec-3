Хотелось бы, чтобы врем было $n\cdot\text{глубина рекурсии}$ для этого нам сделать правильный выбор опорного элемента

Рассмотрим несколько случаев:

### Случайный pivot
$i$ - случайное число $[l, r-1]$
$a[i]$ - pivot

##### Случайные числа в C++
Стандартным `random()` пользоваться нельзя. Он на самом деле не слишком случайный, выдаёт разный результат на разных системах и зачастую выдаёт числа очень маленького размера
В `C++`, начиная с 11 версии лучше всего использовать другой ГСЧ

Все случайные числа зависят от выбранного seed во время создания программы. Лучший вариант - использовать текущее процессорное время

```cpp
#include <iostream>
#include <random>
#include <ctime>


using namespace std;

mt19937 rng(time(NULL));  // mt19937 - тип данных для генератора случайных чисел
						  // rng - название нашего ГСЧ


// генерация числа
int x = rng();
```

Реализация на `C++`:
```cpp
#include <iostream>
#include <vector>
#include <random>
#include <ctime>

using namespace std;

mt19937 rng(time(NULL));

int rand_int(int l, int r)
{
  return uniform_int_distribution<int>(l, r)(rng); // функция, которая
  // генерирует случайное число с интервалом от l до r
}

pair<int, int> partition(vector<int> &a, int l, int r)
{
  // разделить полуинтервал [l, r)
  // вернуть границы разделения
  // (начало центрального блока,
  // начало правого блока)
  auto pivot = a[rand_int(l, r - 1)];
  int k1 = l, k2 = l;
  // k1 - среди уже обработанных элементов начало блока равных опорному
  for (int i = l; i < r; i++)
  {
    if (a[i] <= pivot)
    {
      swap(a[i], a[k2]);
      if (a[k2] < pivot)
      {
        swap(a[k2], a[k1]);
        k1++;
      }
      k2++;
    }
  }
  return {k1, k2};
}

template <typename T>
void quickSort(vector<T> &a, int l, int r)
{
  if (l >= r - 1)
    return;

  pair<int, int> p = partition(a, l, r);
  quickSort(a, l, p.first);
  quickSort(a, p.second, r);
}

int main()
{
}
```


Реализация на `Python`:
```python
from random import randint


def insertion_sort(a):
    n = len(a)
    for i in range(1, n):                               # O(n)
        # пытаемся протащить a[i] влево
        j = i
        while j > 0 and a[j] < a[j-1]:                  # O(n)
            a[j], a[j-1] = a[j-1], a[j]
            j -= 1


def partition(a, l, r):
    # разделить полуинтервал [l, r)
    # вернуть границы разделения
    # (начало центрального, начало правого)
    pivot = a[randint(l, r-1)]
    k1 = l
    k2 = l 
    # k1 - среди уже обработанных элементов начало блока равных опорному
    for i in range(l, r):
        if a[i] <= pivot:
            a[i], a[k2] = a[k2], a[i]
            if a[k2] < pivot:
                a[k2], a[k1] = a[k1], a[k2]
                k1 += 1
            k2 += 1
    return (k1, k2)


def quick_sort(a, l, r):
    # l - начало сортируемого промежутка
    # l - конец* сортиреумого промежутка
    if l >= r - 1:
        return

    px, py = partition(a, l, r)
    quick_sort(a, l, px)
    quick_sort(a, py, r)
```

Есть вероятность, что такая реализация может скатиться в $O(n^2)$. Докажем, что ожидаемое время работы $O(n\log n)$

Мы бы хотели для каждого элемента опредить, в каких рекурсивных вызовах он участвует

Предположим, что элемент оказывается меньше опорного и всегда уходит влево. Нам нужно оценить длину этой цепочки

$$
\begin{array}l 
\text{Начало цепочки: }:  \\
n  & \text{Элементов} \\
 \text{Конец цепочки: }  \\
 1  & \text{Элемент} 
\end{array}
$$

Мысленно разделим массив на 4 блока:
$$
\frac{n}{4} \text{ минимальных }; \frac{n}{4} \text{средних}; \frac{n}{4} \text{средних}; \frac{n}{4} \text{ максимальных}
$$

Если элемент попадает в средние четверти, это хороший исход, если в первую или последнюю - плохой

Если элемент попадает либо во $II$, либо в $III$ четверть, размер большей части $\leq \frac{3n}{4}$

Если элемент попадет в $I$ или $IV$ четверти, это может быть совсем плохое решение


Попробуем выяснить две вещи:
1. Сколько хороших разделений будет в цепочке? 
2. Как часто разделения будут хорошими

#### Сколько хороших разделений в цепочке? 
Количество хороших разделений можно строго определить $\log_{\frac{4}{3}} n$. Эта оценка не зависит от вероятности
$$
\log_{\frac{4}{3}} n 
$$

#### Как часто разделения будут хорошими? 
Если мы берём элемент из центральных четвертей - хорошее разделение, из крайних - плохое разделение $\implies$ вероятность хорошего разделения $\frac{1}{2}$
$$
\leq 2 \log_{\frac{4}{3}} n \qquad \text{ожидаемая глубина рекурсии}
$$

Следовательно, ожидаемое время работы программы $\boxed{O(n\log n)}$

### Интроспективная сортировка
Если мы слишком глубоко уходим в рекурсию, переключаемся на другой метод
Чаще всего для этого используют алгоритм `HeapSort`, который гарантировано работает за $O(n\log n)$

#### QuickSelect
QuickSelect - алгоритм поиска порядковой статистики
$k$-я порядковая статистика - место искомого элемента в отсортированном массиве

Опишем с помощью QuickSort алгоритм выбора порядковой статистики

Возьмём алгоритм со случайным выбором pivot и докажем, что ожидаемое время работы `QuickSelect` = $O(n)$

Потратим $2n$ для того, чтобы распредить хорошее время.
Тогда получим такое время:
$$
2n + f\left( \frac{3n}{4} \right)
$$

$$
2n + \frac{6n}{4} + f\left( \frac{9n}{16} \right)
$$

$$
\frac{18n}{16} + f\left( \frac{27n}{64} \right)
$$

Получим такую последовательность: 
$$
2n+\frac{6n}{4} + \frac{18n}{16} + ..
$$
Бесконечная геометрическая прогрессия

Получим такую сумму:
$$
\frac{2n}{1-\frac{3}{4}} = 8n
$$

Итоговое время будет: 
$$
\boxed{O(n)}
$$
Фактически худший случай: 
$$
O(n^2)
$$

Но этот случай почти никогда не появляется, потому что вероятность появления худшего случая крайне мала и специально его составить невозможно

### Метод Mo5 = Median of 5
Нам нужно сделать QuickSelect. Для разделения выберем опорный элемент, выберем его по стратегии Mo5

Массив разделяется на блоки из 5 элементов, каждый из этих блоков сортируется (с помощью insert sort), из каждого блока выбирается один элемент, который является медианой блока

Теперь, в качестве опорного элемента будет медиана этих $\frac{n}{5}$ элементов, медиану найдём с помощью QuickSelect

Если мы так выберем медиану, то такой опорный элемент окажется очень хорошим, так как в меньшей части у нас будет не меньше чем $\frac{3n}{10}$

Хотя бы $\frac{n}{10}$ выбранных элементов будут меньше опорного

Каждый из таких выбранных элементов тащит за собой ещё несколько элементов меньше опорного

Хотя бы $\frac{3n}{10}$ элементов меньше опорного и хотя бы $\frac{3n}{10}$ элементов больше опорного

На практике достаточно выбора просто случайного элемента

# Метод двоичного поиска или метод бинарного поиска (метод деления пополам)
Основная идея бинарного поиска заключается в том, что у нас есть некое пространство, в котором нам нужно что-то найти

Если мы будем искать последовательно, то для того, чтобы найти элемент, в худшем случае, нам нужно будет просмотреть всё пространство
При бинарном поиске, для того, чтобы найти элемент, нам нужно будет проверить гораздо меньше пространства, так как каждая следующая операция делит размер пространства в два раза

Линейный поиск - $O(n)$
Бинарный поиск - $O(\log n)$

Основное условие бинарного поиска - работает либо на отсортированных массивах, либо на монотонных функциях. Во всех остальных случаях алгоритм не работает

При этом не на любой монотонной функции бинарный поиск может быть применим

Поэтому важна не только отсортированность пространства и монотонность функции, но и определение ответа подходит под бинарный поиск

Существует также интересная модификация, которая называется **бинарный поиск по ответу**

В этой модификации мы пытаемся свести то, что где не работает обычный бинарный поиск к тому, чтобы это заработало

Для этого мы вводим специальную функцию $f(x)$, которая возвращает `Boolean` - результат. Эта функция должна говорить нам, верно ли что ответ на поставленную задачу (то, что мы хотим найти $\geq x$) 
Если рассмотреть значения этой функции в точках, ответы всегда будут выглядеть примерно так:
` T T T T T T F F F F F F F`
Ответом будет являться последнее `True`
Наша задача найти максимальный $x$, для которого $f(x)=$`True`. Такой $x$ мы будем искать с помощью стандартного бинарного поиска

> [!Примечание]
> Бинарный поиск не подходит для поиска экстремума функции

## Нецелочисленный бинарный поиск
Нецелые числа в бинарном поиске:
Есть отрезок $[l; r]$

Проводим поиск, пока $r - l > 10^{-9}$. **Но**! Так в коде писать нельзя
В коде мы можем посчитать количество итераций, необходимых для того, чтобы длину отрезка $r-l$ свести к $<10^{-9}$
