# Проектирование баз данных 
Первое, что создается при создании бд - опрашиваются будущие пользователи системы для определения текущего взаимодействия, на основе чего создаётся концептуальное представление бд в целом

Этапы:
- Концпетуальное проектирование
- Логическое проектирование
- Физическое проектирование
- Собственно база данных и приложения

## Концептуальное проектирование
Концептуальное проектирование - сбор, анализ и редактирование требований к данным

На этапе анализа, как правило, применяются такие методики: методика структурного анализа SADT и основанная на нём IDEF0, диаграммы потоков Гейна-Сарсона, методика объектно-ориентированного анализа UML и другие
Строятся модели предметной области, которые описывают процессы, происходящие в предметной области и данные, используемые этими процессами

Моделирование предметной области - один из начальных этапов проектирвоания, необходимы для выявления, классификации и формализации сведений обо всех аспектах предеметной обласит, определяющих свойства разрабатываемой системы. Затем происходит преобразование ER-модели в конкретную схему базы данных на основе выбранной модели данных

- **Модель данных** - это теория или инструмент моделирования

## Нормализация БД 

- Корректная схема БД - это схема, в которой отсутствуют нежелательные зависимости между атрибутами отношений
- **Функциональные зависимости. Нормальные формы** 
- Каждая нормальная форма это определённый набор ограничений, накладываемый на отношение для улучшения его свойств с точки зрения избыточности данных, потенциально приводящей к аномалиями при модификации данных
- Нормальные формы составляют иерархию, в которой формы с большими номерами не обладают некоторыми нежелательными свойствами, характерными для форм с меньшими номерами. В теории номральных форм для реляционных Бд рассматривается шесть уровней нормализации - 1 НФ - 5 НФ и форма Бойса-Кодда. Каждый из следующих уровней ограничивает типы допустимых зависимостей между атрибутами отношения


Избыточность плоха, потому что она может вызывать: 
- Аномалии вставки
- Аномалии обновления
- Аномалии удаления

Правильная декомпозиция отношений основана на понятии функциональных зависимостей 
Понятие фз является фундаментальным в теории нормализации реляционных баз данных. ФЗ определяют устойчивые отношения между объектами и их свойствами в рассматриваемой предметной области. Именно поэтому прцоесс поддержки ФЗ, характерных для данной предметной области, является базовым для процесса проектирования БД 

*Определение*.
Пусть $R$ - отношение. Множество атрибутов $Y \subset R$ функционально зависимо от множества атрибутов $X \subset R$ ($X$ функционально определяет $Y$) для любого состояния отношения $R$ для любых кортежей `r1, r2` $\in R$ из того, что $r_{1}.X=r_{2}.X$ следует что $r_{1}.Y=r_{2}.Y$. Символически фз записывается $X\to Y$ множество атрибутов $X$ называется детерминантом фз, а множество атрибутов $Y$ называется зависимой частью

ФЗ в отношении $R$ называется транзитивное, если существует такой атрибут $B \subset R$, что имеются функциональные зависимости $A \to R$, $B \to R$

Множество ФЗ называется неприводимым (минимальным) тогда и только тогда, когда оно обладает всеми тремя перечисленными свойствами: 
1. Правая часть каждой ФЗ из множества $S$ содержит только один атрибут
2. Левая часть каждой ФЗ из множества $S$, в свою очередь, является неприводимой, т.е. ни один атрибут из детерминанта не может быть опущен без изменения замыкания $S+$. В этом случае ФЗ называется неприводимой слева
3. Ни одна ФЗ из множества $S$ не может быть удалена из множества $S$ без изменения его замыкания $S+$
