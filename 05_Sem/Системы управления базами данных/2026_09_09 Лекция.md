# Введение в базы данных
Данные бывают взаимозависимыми, причём, число связей по мере детализации постановки задачи увеличивается. Взаимосвязанные данные называют **системами данных**

Хранилища данных часто называют **системами хранения информации**

Отличие между базой данных и просто хранилищем:
База данных - архивный шкаф с картотекой
Файловое хранилище - куча бумаг на столе

## Правила построения базы данных
1. **Структура и формат данных**
   Баз данных строго структурированы. Эта структора может быть жёсткой (реляционные БД) или мягкой (NoSQL), но она есть
   В **общем файле** структуру внутри контролирует приложение и, если что-то пойдёт не так, то ошибочные данные просто сохранятся в файл
2. **Одновременный доступ (конкуренция)**
   **Базы данных**, как правило, поддерживают многопользовательский режим, обеспечивая точность и непротиворечивость данных, используя механизмы блокировок (Locks) или многоверсионность (MVCC). Здесь работает протокол (ACID) - (Атомарность, согласованность, изоляция, долговечность) 
   В **общем файле** если, например, одновременно менять одну и ту же ячейку, то Excel предложит выбрать, чьи изменения сохранить. Если менять разные ячейки - конфликт
3. **Производительность при поиске**
   **БД** применяют различные механизым оптимизации для поиска данных. Например, используя индексы в виде B-Tree деревьев
   **Общий файл**. Чтобы найти строку в большом CSV-файле, приложению нужно прочитать файл целиком с начала до конца $O(n)$ сложность. Это убивает производительность при росте данных
4. **Транзакционность** (свойства ACID)
   **БД** гарантирует свойства ACID. Если вы переводите деньги со счёта A на счёт B, и сервер упал в середине операции - бд откатит изменения (Rollback). Деньги не пропадут
   Если во время записи в **общий файл** выключилось питание, файл будет повреждён (записан наполовину). Восстановить целостность можно вручную с помощью резервной копии
5. **Безопасность**
   **База данных** имеет встроенную систему ролей (Grant/Revoke). Можно давать доступ и разрешение на различные действия для различных объектов БД
   В **общем файле** безопасность строится на правах доступа файловой системы. Если пользователь может читать папку - он читает весь файл целиком. Спрятать одно поле внутри файла от конкретного пользователя невозможно
6. **Резервное копирование**
   
## Когда файлы лучше БД?
- Медиа-контент
- Обмен данными между разными системами
- Очень простые, однопользовательские приложения

## Для чего нужны БД?
Базы данных нужны, чтобы хранить, быстро находить, орабатывать и защищать инфомрацию

**База данных** - совместно используемая совокупность связанных данных о конкретной предметной области, в которой определение данных и отношений между ними (структура данных) отделены от процедур их обработки
- Надёжное и безопасной хранение
- Быстрый поиск
- Совместная работа без конфликтов
- Поддержка связей между объектами предметной области

Взаимодействие с БД всегда строится через систему управление базой данных

Любая БД состоит из 4-х основных компонентов
- данные
- аппаратное обеспечение
- программное обеспечение
- пользователи

### Аппаратное обеспечение БД
**Ключевые аппаратные компоненты** - CPU, RAM, Storage
**Архитектурные подходы**: 
- **Общие диски**. Все серверы имеют доступ к одному массиву дисковых данных
- **Общая память**. Мультипроцессорные системы с общей для всех CPU памятью
- **Ничего общего**. Доминирующий подход в высоконагруженных системах. Каждый узел имеет свои собственные апаратные средства

### Программное обеспечение
Основные функции СУБД:
- Управление данными во внешней памяти
- Управление данными в оперативной памяти
- Журнализация изменений, резервное копирование и восстановление бд после сбоев
- Поддержка языков БД. Язык определения данных - создание, изменение, удаление объектов БД и язык манипулирования данными
- Подерка целостности данных
- Управление параллельной работой
- Защита от несанцкионированного доступа

#### Архитекутора СУБД
**Архитектура СУБД** - внутренняя структура системы, определяющая, как она взаимодействует с пользователем

##### Трёхуровневая
Три уровня:
- Внутренний (представление физического хранения)
- Концептуальный (обобщенное представление пользователя)
- Внешний уровень (представления отдельных пользователей)

##### Распределённая
Данные физически хранятся на нескольких серверах, которые работают как единое целое. Клиенту кажется, что он работает с одной большой БД 

##### Встраиваемая СУБД
Это библиотека, которая встраивается прямо в приложение и работает внутри его процесса
Не требует отдельного сервера и настройки

##### Облачные СУБД
База данных работает в облаке провайдера. Пользователь не управляет серверами, дисками и бэкапами и просто использует БД 

#### Внутреннее устройство СУБД
- Диспетчер запросов
- Оптимизатор запросов
- Исполнитель
- Менеджер транзакций
- Менеджер буферов
- Менеджер хранилища

# Модели данных 
Каждая СУБД поддерживает некоторую модель данных, являющуюся формальной теорией представления и обработки данных. Все СУБД, построенные на одной и той же модели данных, относят к одному типу.

Модель данных включает, по меньшей мере, три аспекта:
- **аспект структуры**: методы описания типов и логических структур данных в БД 
- **аспект манипуляции**: методы манипулирования данными
- **аспект целостности**: методы описания и поддержки целостности БД

## Реляционная модель
Целью разработки реляционной моедли было стремление создать структурно простую модель с чётким разделением логических и физических аспектов организации и управления БД

### Стркутурная част реляционное модели
Включает следующие объекты: *домены*, *атрибуты*, *кортежи*, *отношения*, *потенциальные (возможные) ключи*, *первичные ключи*

Наименьшей единицей данных реляционной моедил является атомарное (неразложимое) для данной предметной области значение данных

**Домен** - множество допустимых атомарных значений одного и того же типа. Понятие домена несет семантичесую нагрузку: данные можно сравнивать, только если они относятся к одному домену. Например, домены цена и вес относятся к вещественному типу данных, но сравнивать значения их этих доменов не имеет смысла
